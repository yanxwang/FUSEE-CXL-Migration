5.7 Mops/s; that did **not recur** in the later sweep (48.4 Mops/s).

Small C dips on workload-f T=8 (−15 %) are in the run-to-run noise
envelope at that T / workload mix.

## Phase 2 disposition

`FUSEE_USE_TICKET_LOCK=ON` build flag swaps LFM → ticket lock.
Intra-host ticket lock at N=1..4 beats LFM 1.4-5.6×. Cross-host atomic
`fetch_add` works with explicit `flush_line` before+after (proven by
`tests/cxl_atomic_xhost`).

But enabling it in the YCSB runner causes a hang I couldn't diagnose
in the time allotted — the atomic microbench passes, the lock's own
decomp bench passes at N=1..4, but the runner's 65 536-bucket init +
concurrent lock()s deadlock. Default build continues to use LFM so the
regression doesn't leak into the main sweep.

Finding doc: `docs/g34_scaling_ycsb/phase2_ticket_lock_findings.md`.
